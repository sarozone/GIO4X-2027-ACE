# Multi-language: preparation

Status on 5 October 2026: **seven languages have four pages each; section 6 says exactly what exists.**
Sections 1 to 5 are the preparation as written on 3 October 2026, when the status was: **English only. Nothing is translated and no code was changed for this.** The site must not
be machine-translated: it carries risk warnings, legal documents and descriptions of financial
products, and a wrong sentence in any of them is a compliance problem, not a typo. This document
sizes the work, recommends an approach for this codebase, lists what only the owner can decide and
sets out a phased plan.

## 1. How much there is

Measured on the repository on 3 October 2026 by counting prose string literals and JSX text
(`src/app/(site)`, `src/components` without the staff console, `src/data`, `src/config`). Treat the
figures as rough: the count cannot tell a sentence from a long label with certainty.

| Where the words live | Files | Prose strings (approx.) | Words (approx.) |
|---|---|---|---|
| Typed content: `src/data/*.ts` and `src/data/generated/*.json` (glossary, Academy, articles, instruments, knowledge, FAQs, legal documents, tools, platforms) | 29 | 3,900 | 82,000 |
| Page files: `src/app/(site)/**` | 83 | 4,400 | 29,000 |
| Components: `src/components/**` (tools, labs, desk, tour, shell, figures) | 391 | 4,200 | 28,000 |
| Configuration: `src/config/*` (navigation, legal strings, site facts) | 5 | 50 | 400 |
| **Total** | | **about 12,500** | **about 140,000** |

Pages: 75 page templates under `src/app/(site)`, which generate several hundred addresses (139
carried glossary terms plus those added in `src/data/glossary.ts`, about 30 instruments, the Academy
lessons, 11 articles, twelve tools, the event explainers, the central banks and the legal
documents). The portal in `portal/` and the staff console under `/control` are separate and are not
counted.

Things that are not prose but are language-dependent:

- Numbers, money and dates are formatted with `en-GB` in several places (`src/components/tools/calc.ts`,
  `src/lib/rates.ts`, `toLocaleDateString("en-GB", …)`).
- `<html lang="en">` in `src/app/layout.tsx`; Open Graph `locale: "en_GB"` in `src/lib/meta.ts`.
- Search (`src/lib/search.ts`, `src/lib/search-index.ts`): aliases, typo tolerance and the command
  words ("switch dark mode") are English.
- Text inside drawings: SVG and canvas figures carry labels as code (`src/components/figures/**`,
  the simulator chart, tool visualisers).
- Share cards (`opengraph-image.tsx`) use Latin-subset TT Norms (`src/fonts/`). A language outside
  that subset needs another font file for cards and for headings.
- Structured data, the sitemaps, `llms.txt`, the RSS feed and `src/config/redirects.json`.
- The fonts and layout are left-to-right only. A right-to-left language is a design project of its
  own, since the φ grids (`.phi`, `.phi-r`) and every directional icon would need mirroring.

## 2. Where copy lives today

There is no message catalogue. Copy is written where it is used:

1. **Data modules** hold most of it, already as typed objects, which is the easy part to translate:
   one object per glossary term, lesson, instrument, tool, FAQ and legal document.
2. **Page files** hold headings, leads and paragraphs inline in JSX.
3. **Components** hold labels, hints, error messages, narration (tools, practice desk, tours) and
   strings built from numbers with template literals, which is the hard part: word order and
   plurals differ between languages.
4. **`src/config/legal.ts`** holds the risk warning and company line, carried over verbatim.

## 3. Recommended approach

### 3.1 A `[lang]` route segment, not a cookie

Recommended: **a locale in the path** (`/ar/markets`, `/es/markets`), with English left at the root
so that no existing address changes.

| | `[lang]` segment | Cookie or header |
|---|---|---|
| Static generation | Kept: each language is its own set of static pages | Lost: one address with different content forces dynamic rendering or `Vary`, on a site that is almost entirely static |
| Search engines | One address per language, `hreflang` between them, a sitemap per language | One address; translations are effectively invisible to search |
| Sharing a link | The link carries the language | The recipient gets their own language, not the sender's |
| CDN caching (Netlify) | Simple | Needs cache variation by cookie |
| Privacy posture | No new stored value | A new stored value to list on `/preferences` and in the Cookie Notice |
| Cost | The route tree moves under a segment | Small at first, expensive later |

A remembered choice can still be added on top: a `lang` field in `gx:prefs` used only to offer
"Continue in Español?" on an English page. It never redirects by itself.

### 3.2 Shape in this codebase

- **Routing.** Add `src/app/(site)/[lang]/…` for translated languages and keep the existing tree as
  English (`x-default`). Do not use `dynamicParams = false` (see `docs/ARCHITECTURE.md`: it breaks
  prerendered dynamic routes on the Netlify runtime); validate `lang` and call `notFound()`.
  `src/middleware.ts` is scoped to `/control` and stays that way: no language negotiation in
  middleware.
- **A page that is not translated does not exist in that language.** It is not served in English
  under a translated address. The language switcher links only to pages that exist, and falls back
  to the English address openly ("This page is available in English").
- **Dictionaries, no dependency.** The project rule is no new runtime dependencies, and the App
  Router does not need one. Use typed dictionaries: `src/i18n/en.ts` as the source of truth,
  `src/i18n/<lang>.ts` typed `typeof en`, so a missing key fails `tsc`. A server helper
  `getDictionary(lang)` passes only the slices a client leaf needs as props.
- **Content data.** Split each data module into facts and words: numbers, slugs and relations stay
  in `src/data/*.ts`; the words move to `src/data/<lang>/*.ts` with the same keys. Slugs stay
  English in every language at first (stable links, simpler `hreflang`).
- **Sentences built from numbers** (tools, practice desk, account chooser, tours) become functions
  in the dictionary: `result: (n: number, unit: string) => string`. Plurals use
  `Intl.PluralRules`; numbers and dates use `Intl.NumberFormat` and `Intl.DateTimeFormat` with the
  page's locale in place of the hard-coded `en-GB`.
- **Metadata.** `pageMeta` (`src/lib/meta.ts`) gains `lang` and emits `alternates.languages`
  (`hreflang`) only for languages in which the page exists. `<html lang>` moves into a layout that
  knows the segment. One sitemap per language (`src/lib/sitemap-data.ts`).
- **Search.** One index per language (`/search-index.<lang>.json`); aliases and command words are
  part of the translation.
- **Legal strings.** `src/config/legal.ts` becomes per-language only with the approved text in hand.

### 3.3 What must not be done

- No machine translation published without a qualified human's review, anywhere.
- No client-side translation widget or third-party script (the CSP forbids it, rightly).
- No mixed pages: an English risk warning under a translated page is acceptable only if the owner
  and counsel say so explicitly; a translated warning that nobody approved is not acceptable at all.
- No translated page for a jurisdiction where the services are not offered (see
  `restrictedJurisdictions` in `src/data/accounts.ts`) without a decision on record.

## 4. What the owner must decide

1. **Which languages**, in order, and whether any is right-to-left.
2. **Why each one**: which audiences, in which countries, and whether GIO4X may market to them
   there. A language is read by regulators as an intention to serve its speakers.
3. **Who translates and who approves.** A named, qualified translator per language with financial
   vocabulary, and a named approver inside GIO4X. Recorded in the same way as the editorial
   standards (`/trust/editorial-standards`).
4. **Legal pages.** Whether Terms, Risk Disclosure, Privacy, AML and Cookies are translated; if so,
   by whom, and which version prevails in a dispute (normally the English one, stated on the page).
   Until a legal page is approved in a language, it is linked in English from that language.
5. **Scope of the first release.** All of it is about 140,000 words. A first release of the core
   journey is a fraction of that (see phase 2).
6. **Editorial content.** Whether articles and the Academy are translated at all, or stay English
   with a plain notice.
7. **Support.** Whether enquiries in that language can be answered, and by whom. A translated
   contact form with nobody to reply is worse than an English one.
8. **The portal.** Whether `/portal` (a separate application in `portal/`) will match. A translated
   website that hands over to an English sign-up should say so before the button.
9. **Upkeep.** Who is told when an English page changes, and how long a translation may lag before
   the page is withdrawn in that language.
10. **Product and brand terms** that stay untranslated: GIO4X, 777 Raptor, MetaTrader 5, Classic,
    Premium, ECN, and whether "The Gentleman's Brokerage House" is translated.

## 5. Phased plan

**Phase 0: decisions (owner).** Section 4, items 1 to 5 at least. Nothing is built before this.

**Phase 1: make English translatable, change nothing visible.**
- Introduce `src/i18n/en.ts` and move shell copy into it (header, footer, navigation labels from
  `src/config/nav.ts`, command bar, cookie and privacy controls, error and empty states).
- Replace hard-coded `en-GB` formatting with one locale-aware formatter module.
- Add `lang` to `pageMeta` and the root layout, defaulting to English.
- Check: the built English site is identical before and after.

**Phase 2: the core journey in the first language.**
- Home, Markets overview, Trading (accounts, chooser, conditions, funding), Platforms, the tools
  hub and the twelve tools, Open an account, Sign in, Contact, FAQ, Trust centre, and the legal
  pages or their approved English links. Roughly 25 templates.
- `[lang]` routes, `hreflang`, the language sitemap, a language switcher in the header popover.
- Human translation, then review by the named approver, then a second reader for the risk warnings.

**Phase 3: the knowledge base.**
- Glossary and instruments (structured, repetitive, the best value per word), then event and
  central-bank explainers, then the Academy.
- Per-language search index and aliases. Labels inside figures.

**Phase 4: editorial and the long tail.**
- Articles (only if there is an editor for that language), Labs, the practice desk narration, tours,
  share cards with a suitable font.

**Phase 5: upkeep.**
- A build check that fails when a translated dictionary is missing a key, and a report of English
  strings changed since their translation was approved.
- A dated "translated on / reviewed by" line on translated legal and risk pages.

Each phase ships only complete pages. A half-translated page is not published.

## 6. What exists since 5 October 2026

The owner decided the languages on 5 October 2026: **Hindi (hi), Tamil (ta), Arabic (ar, right to
left), Spanish (es), Portuguese (pt), French (fr) and German (de)**. English stays the default at the
addresses it has always had. This first release adds pages; it moves and rewrites nothing.

### 6.1 The pages

Four pages per language, 28 addresses in all, and no others:

| Address | What it is | "English" in the switcher leads to |
|---|---|---|
| `/<lang>` | The home page of that language: what GIO4X is, the markets, the two platforms, the three accounts, tools, learning, the Trust Centre, contact, and where the services are not offered | `/` |
| `/<lang>/guide` | The site guide: each main section of `src/config/nav.ts` described, with its English pages listed beneath it | `/explore` |
| `/<lang>/risk-warning` | The risk warning and company line of `src/config/legal.ts` translated, the English original beneath, and the statement that the English text prevails | `/legal/risk` |
| `/<lang>/contact` | How to reach GIO4X: `info@gio4x.com`, the English contact form and support requests (both linked as English), the two postal addresses | `/contact` |

Every one of them opens with a notice in its own language: the translation is provided for
convenience, is awaiting review by a qualified translator, and the English version prevails. Every
link that leaves these four pages carries the mark "in English" in that language. Nothing else is
served under a language's address: `/de/markets` is a 404, as the plan requires.

### 6.2 Where the code is

- `src/i18n/config.ts`: the languages (code, native name, direction, language tag, Open Graph
  locale), `isLocale()`, the list of translated pages, the English page each stands beside,
  `hreflang` and the sitemap addresses. No copy; safe in client components.
- `src/i18n/en.ts`: the source dictionary. `src/i18n/<lang>.ts`: one per language, typed
  `Dictionary` (`typeof en`), so a missing or misspelt key fails `npx tsc --noEmit`.
  `src/i18n/index.ts`: `getDictionary(lang)` and `localiseValue()`.
- `src/i18n/shell.ts`: the ten words of the header that follow the page's language (the six
  section names, Search, Sign in, Open account, Language). The only translation in the client bundle.
- `src/app/(site)/hi`, `ta`, `ar`, `es`, `pt`, `fr`, `de`: one fixed folder per language, each with
  `layout.tsx`, `page.tsx`, `guide/`, `risk-warning/` and `contact/`: a few lines that hand the
  language to the real pages in `src/components/i18n/pages/` (`layout.tsx`, which sets `lang` and
  `dir` on the page and loads `src/styles/i18n.css`, `home.tsx`, `guide.tsx`, `risk-warning.tsx`,
  `contact.tsx`). A dynamic `[lang]` segment was tried first and withdrawn the same day: it caught
  every unknown first segment and, because the site streams a loading state, `/zzz` answered 200
  where it used to answer 404. Adding a language is a new folder of the same five files.
- `src/components/i18n/`: `LocaleDocument.tsx` (sets `<html lang>` and `dir` while a translated page
  is open and puts English back on leaving) and `Translated.tsx` (the notice, the "in English" mark,
  the list of restricted jurisdictions).
- `src/components/shell/LanguageSwitcher.tsx`: a popover in the header from 1280px up, a list in the
  phone and tablet drawer, and a list in the footer on every page. Between 1080px and 1279px the
  header row has no room for another control (it is already full at 1080px), so at those widths the
  choice is in the footer and in the notice at the top of each translated page.
- `src/styles/i18n.css`: system-font aliases for Devanagari, Tamil and Arabic (no font file is
  added; TT Norms and Inter still set every Latin letter), no letter-spacing and looser leading for
  those scripts, and the right-to-left rules. Only the translated page runs right to left; the
  English header and footer round it stay left to right.
- Changed, each by a few lines: `src/lib/meta.ts` (`pageMeta` takes optional `languages` and
  `locale`; without them its output is what it was), `src/app/(site)/page.tsx` (the English home
  page lists its seven counterparts as `hreflang`), `src/lib/sitemap-data.ts` (the 28 addresses, in
  `/sitemap-pages.xml`), `src/components/cockpit/routes.ts` (each translated page borrows an existing
  scene), `SiteHeader.tsx` and `SiteFooter.tsx` (the switcher, and the header's words).

### 6.3 Rules the pages keep

- **No figure is typed into a translation.** Counts (asset classes, instruments, tools, lessons,
  glossary terms) and the account figures are read from `src/data/*` when the page is built; a
  sentence that carries a number is a function in the dictionary. The published account values keep
  their figures and have only their words exchanged (`localiseValue`).
- **The list of restricted jurisdictions is read from `restrictedJurisdictions`** when the page is
  rendered, never copied, and is shown with its English names.
- **The English risk warning is read from `src/config/legal.ts`**; its translation is in each
  dictionary (`risk.warning`, `risk.company`). When the English wording changes, all seven must be
  revised with it.
- **No claim the English site does not make**: no regulator, no unverified figure, "technology
  provided by 777 Raptor", MetaTrader 5 as a third-party platform, no telephone number or hours.
- **`hreflang`**: the home page in each language and the English home page name each other, with
  `x-default` on English. The other three pages name their seven versions and give the nearest
  English page as `x-default` only, because no English page has the same content.
- **Indexing** is unchanged: nothing is indexed outside the production environment.

### 6.4 What is not translated

Everything else, about 140,000 words (section 1): every market, instrument, tool, lesson, glossary
term, article and Lab; the mega-menu's contents and the footer directory; the announcement line, the
command bar and search; the contact and support forms; the 404 page; share cards; structured data;
`llms.txt`; the RSS feed; the portal. **The legal documents stay English** and are linked as English
from every language. Numbers on the translated pages keep the English formatting of the data
(`$2,000`, `2.5`).

### 6.5 What the owner still has to supply

1. **A named, qualified reviewer for each of the seven languages**, with financial vocabulary, and a
   named approver inside GIO4X (section 4, item 3). Until a language is reviewed its notice stays.
   The risk warning in each language should be read first, and by a second reader.
2. **The decision on translated legal pages** (section 4, item 4): whether Terms, Risk Disclosure,
   Privacy, AML and Cookies are translated, by whom, and the statement of which version prevails.
3. **Support in each language** (section 4, item 7): whether an enquiry written in Hindi, Tamil,
   Arabic, Spanish, Portuguese, French or German can be answered in that language, and by whom. The
   contact pages currently say that a reply may be in English.
4. **Which Portuguese and which Spanish.** Portuguese is written in the Brazilian standard and
   Spanish in a neutral European-leaning one; the Open Graph locales are `pt_BR` and `es_ES`.
5. **The audiences** (section 4, item 2). Several countries where these languages are spoken are on
   the list of restricted jurisdictions (for Arabic: Egypt, Iraq, Lebanon, Libya, Somalia, Sudan,
   Syria, Tunisia, Yemen; for Spanish: Cuba, Nicaragua, Venezuela), and since 5 October 2026 so are
   the United Kingdom and the United States. Each translated home page and risk page shows the list.
   A decision on record is still needed for each language (section 3.3, last point).
6. **Whether "The Gentleman’s Brokerage House" is translated.** It is shown in English with one
   sentence of explanation in each language.
7. **Upkeep** (section 4, item 9): who is told when the English risk warning, the wording of the
   account figures or the navigation changes.

- The seven home pages and their three sub-pages are prerendered (28 static pages).

### 6.7 Nineteen more languages (5 October 2026, later the same day)

At the owner's instruction the same four pages (home, site guide, risk warning, contact) were added in:
Telugu `te`, Malayalam `ml`, Kannada `kn`, Bengali `bn`, Marathi `mr`, Gujarati `gu`, Urdu `ur` (right to
left); Japanese `ja`, Korean `ko`, Thai `th`, Vietnamese `vi`, Filipino `fil`; Italian `it`, Dutch `nl`,
Polish `pl`, Greek `el`; Swahili `sw`, Afrikaans `af`, Amharic `am`. Twenty-six languages in all, 104
translated addresses. Chinese, Indonesian, Malay, Russian and Turkish were left out on purpose: the
countries they would chiefly address are on the restricted list (section 3.3).

Each is a dictionary in `src/i18n/<code>.ts`, a line in `LOCALES` (`config.ts`), a line of header labels
(`shell.ts`) and a folder of five small files under `src/app/(site)/<code>`. Scripts the brand faces do not
carry use the reader's system fonts (`src/styles/i18n.css`); no font file was added. The language menu
scrolls inside its panel.

Everything in sections 6.4 and 6.5 applies to these with more force: none has been read by a native
reviewer, every page says so, and the English text prevails. The terms each translator would have a
reviewer check first are recorded in the commit that added the languages. Bengali leans to Bangladesh
spelling, Portuguese is Brazilian, Spanish European: the audience for each is the owner's to confirm.

### 6.8 The glossary and the contact form in every language (5 October 2026)

**A fifth page, `/<lang>/glossary`** (26 more addresses, 130 translated addresses in all). It lists every
term of `src/data/glossary.ts` with its name and definition in the language, its topic, and a link to the
English entry, marked "in English", where the formula, the example and the related terms stay. A term a
language does not carry yet is shown in English and says so. "English" in the switcher leads to `/glossary`.

- `src/i18n/glossary/<code>.ts`: one file per language, `Record<slug, { term, definition }>`
  (`types.ts`). `src/i18n/glossary/index.ts`: `getGlossaryWords(lang)`, one `import()` per language, so
  a language never loads with another. The list, its order and the topics are read from the English data.
- `src/i18n/glossary-page.ts`: the page’s own words (title, filter, counts, the eight topic names) for the
  26 languages, typed so that a missing language or line fails `tsc`. No dictionary was touched.
- `src/components/i18n/pages/glossary.tsx` (the page) and `src/components/i18n/GlossaryList.tsx` (search
  box and topic filter; the whole list is in the HTML). The English index (`GlossaryIndex`) is not reused:
  it files terms under A to Z and carries the lessons’ progress marks, neither of which translates.
- Everything else follows from `LOCALE_PAGES` in `config.ts`: the language switcher, `hreflang`
  (`x-default` is `/glossary`; the English page is not named as a counterpart, and is unchanged), the
  sitemap, the hero scene (`lexicon`, in `cockpit/routes.ts`) and the label on `/explore/sitemap`.
- The translated home page and the Academy entry of the site guide link to it.

**The contact form on `/<lang>/contact`.** The page now renders the real form, not a link to the English
one. `src/components/company/ContactForm.tsx` takes an optional `words`; without it every string is the
English it has always been, and the English page’s HTML was compared before and after and is identical.
`src/i18n/contact-form.ts` holds the 26 translations (labels, hints, placeholders, validation messages,
button, success and failure states, the ten topics as displayed), typed by the form.

- **What is sent is unchanged**: the topic travels as its English name (`CONTACT_TOPICS` in
  `src/lib/server/constants.ts`), and `page` is the translated address, which tells whoever answers
  which language the visitor was reading.
- A message the server returns is in English; it is shown as English after a line in the page’s language.
- Links inside the form that lead to English pages (the Privacy Policy, the page that may already answer)
  carry the "in English" mark. The page says that a reply may be in English (section 6.5, item 3).
- Right to left (`ar`, `ur`): the form uses logical sides when it is translated; email and telephone
  fields and the character count stay left to right.

Still English, and known: the sentence on each translated home page that lists the translated pages does
not yet name the glossary, and `contact.formBody` / `contact.formLink` in the dictionaries are no longer
shown. Both are dictionary changes (27 files) left for the next revision of the dictionaries. As with
everything in 6.7, none of this has been read by a native reviewer.
